# Contributing to Ark Arena Architect

Thank you for improving this project.

## Workflow

1. Create a focused branch from `main`.
2. Make the smallest complete change that solves the problem.
3. Run the available tests, linting, and build checks.
4. Update documentation when behavior changes.
5. Open a pull request describing what changed, why it changed, and how it was verified.

## Commit quality

Use clear, imperative commit messages. Never commit passwords, access tokens, private keys, `.env` files, dependency folders, or generated build output.

## Pull requests

A pull request should be reviewable, reproducible, and limited to one logical change whenever practical.
